# 独立逐树参考程序的float32边界修正

原audit.py、model.py及失败audit.log均未改动。首次audit在raw_f0的16个检查样本之一
发现参考margin相差.020946；保存模型重放与保存概率已逐位一致，差异出现在独立参考。
原参考把get_dump输出的十进制阈值直接当作Python双精度数比较，XGBoost使用float32。
在阈值附近这会改变分支，不能通过放宽输出容差来解决。

新版独立参考读取完整保存模型的索引树数组，把split_conditions和输入显式还原float32，
逐节点遍历并以float64累计叶值，再以原相同atol5e-5/rtol2e-5核对原margin。
每个选择模型另选前6个分裂阈值，检查float32阈值本身及nextafter上下相邻数值；
这些边界点也由完整模型预测和独立参考交叉验证。遍历不是调用库预测模拟输出。

没有重新训练或改写任何已保存树/特征/概率/选轮，未改模型、双指标推进门槛或容差。
这与冻结前树输入浮点不稳定问题不同：前者改变特征设计保证删查询输入逐位相等，
此处仅修复独立审计器对序列化阈值的数值语义。完整真实删查询检查继续使用原容差。
