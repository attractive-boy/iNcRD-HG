# 更值得大幅改动的方向：区分情境反转与证据冲突

2026-09-09 补充核查：32 个优先配对中，16 个配对的部分候选证据来自 PMID 24145123 的耐药株–亲本表达芯片比较；这些记录本身没有测量相应 miRNA 的干预效应。该论文另有 miR-203 功能实验，不能投射到全部芯片条目。原清单仍是待核查的注释候选，未经自动删改。更具体的证据语义核查、已有方法边界和干预预测方案见 [后续创新判断](../intervention_design_20260909/ASSESSMENT.md)。

建议把下一条研究问题具体化为：**同一个 miRNA–drug 配对，在什么细胞状态下被记录为耐药相关、在什么状态下被记录为敏感相关？模型能否区分有依据的方向反转、文献分歧和证据不足？**

这改变了预测对象和证据组织方式。它目前是研究提案，尚未实现为新模型，也没有完成穷尽式新颖性核验。不能宣称首次研究情境依赖、方向预测或证据可靠性。

## 现有数据已经支持走到哪里

方向来自 ncRNADrug 的原始 Effect 字段，经既有 direction_labels.py 提取；上下文来自 Condition 字段的拆分。此前的纯关联实验没有使用这些方向标签，但工作区已经有方向预测和癌种上下文模型，不能把“加一个癌种 embedding”重新作为新贡献。

本次额外审计用 Cellosaurus 的唯一 accession 合并别名，拒绝一对多的歧义映射；每个 PMID 在同一个配对、细胞系、方向上只计一次。

| 审计项 | LncDir | MiDir |
|---|---:|---:|
| 原始方向记录 | 2,451 | 10,506 |
| 原始 RNA–drug 配对 | 2,108 | 5,393 |
| 具有两种方向的原始配对 | 56 | 1,107 |
| 同一标准细胞系内仍有方向冲突的配对–细胞系组合 | 11 | 476 |
| 不同上下文方向相反、每个已映射上下文内部一致的候选配对 | 32 | 492 |
| 上述候选中存在同一 PMID 内相反方向记录的配对 | 0 | 21 |
| 上述候选中两种方向分别有多篇 PMID 记录的配对 | 0 | 11 |

后两组 miRNA 候选互不重叠，合计 **32 个优先核查配对**。它们是注释层面的候选，不是已经确认的实验反转。所有未映射/歧义细胞系均不进入严格计数，因此“上下文内部一致”只适用于通过映射的证据。

不能把 1,107 个矛盾配对都当作真实反转。仅仅细分上下文、让矛盾在表格中消失，可能是按不同论文拆开了证据；这不能证明上下文本身造成了方向变化。

## 可以提出的新机制假设

将每条原始记录保留为带来源的证据对象，而不是先把多条记录合并成一条确定标签：

- **生物上下文部分**：RNA、drug、细胞状态共同产生一个方向评分，允许同一配对随状态改变方向。
- **来源部分**：显式建模研究/实验条件差异与噪声。论文编号只用于训练分组、来源效应和不确定性建模；新论文预测时不能依赖记住该论文的标签。
- **反转部分**：直接比较同一 RNA–drug 配对在两个上下文中的评分差，而不是只优化所有三元组混在一起的 AUC。
- **保留不确定性**：证据冲突与缺乏覆盖分别呈现；不强制把每个配对压成唯一方向。

一个可实现的起点是“方向评分＋研究随机效应＋记录级多实例观测模型”。同一 Condition 列表含多个细胞系时，保留原始 record 作为一个观测单元，避免把一次注释展开后当作多次独立实验。来源效应和真实情境效应的可分辨性依赖跨来源、跨上下文的证据重叠，不能仅靠加两个网络头保证。

这比模块命名更具体的可检验主张是：**保留矛盾证据及其来源，有助于预测新研究中的情境方向变化，并识别现有证据不足以判断的配对。** 是否成立要由实验决定。

## 先做的证据核查

1. 从 PRIORITY_PAIRS.csv 的 32 个 miRNA–drug 配对开始，沿 PRIORITY_EVIDENCE.csv 中的 PMID 检查原始研究。
2. 核实 Effect 描述的是 RNA 对药物反应的作用，还是不同干预方向/表达变化下的结果；核实同文献内的两个条件确实可比较。
3. 保留敲低/过表达、剂量、时间、耐药衍生株等条件，不把数据库拆出的细胞系列表自动当作逐细胞系独立测量。
4. 核对相应细胞状态是否有可用的表达或其他特征。现有 CCLE 的 938 个细胞系不能自动代表全部文献细胞系和耐药衍生株。

目前不适合承诺双 RNA 任务都能做成：lncRNA 侧没有达到同样来源支持条件的优先候选，主线应先从 miRNA 开始。

## 怎样证明不是靠先验或调参

| 对照/划分 | 要回答的问题 |
|---|---|
| 已有 pair 模型、已有 triple+c 模型 | 新结果是否只是复现“加入癌种”这一已有改动？ |
| RNA、drug、cancer 方向比例先验 | 模型是否只记住某类节点通常偏向哪个方向？ |
| 保留全部标签但移除来源建模 | 来源部分是否提供增量？ |
| 相同拟合集内打乱上下文与记录的对应关系 | 收益是否依赖真实上下文对应关系？ |
| PMID 分组留出、记录级去重 | 同一论文或展开记录是否跨越训练与评估？ |
| 配对/新 RNA 留出及时间留出 | 是否能推广到未见配对或后来的证据？ |
| 同配对跨上下文的方向差排序、拒判后的覆盖率与错误率 | 是否真的识别反转，并知道何时证据不够？ |

各方法使用同样内部调参预算；正式判断前固定超参数和划分。只有 21 个同文献支持候选和 11 个多来源候选，不足以单独承担大模型训练，应先用于证据复核和小规模验证设计。

## 可复用产物

- AUDIT.json：输入与代码哈希、覆盖率和全部计数。
- PRIORITY_PAIRS.csv：32 个优先核查配对。
- PRIORITY_EVIDENCE.csv：对应的方向、PMID、原始实验条件、年份及标准细胞系 ID。
- MiDir/evidence.csv、pair_contexts.csv、pair_audit.csv：保留来源的全量标准化证据及冲突审计。
- LncDir/ 下保留相同审计结果，避免只报告 miRNA 的有利部分。

既有工作区实现可见 /data1/licheng/incrd-hg/incrd-run/analysis/context_model.py 和 context_controls.py；它们是此前已有工作，不是本轮新增成果。本轮新增的是严格的来源/细胞系审计、优先核查清单及上述待检验问题。
