# 药物条件的多正例集合去噪

本轮验证 [创新提案的第一条](research/innovation_directions_20260910/PROPOSAL.md)：使用完整 RNA 候选集合与正关联遮蔽训练，检验能否改善同药物排序，同时保住全局 AP/AUC。

**2026-09-11：冻结实验已完成，当前原型未通过预设性能与机制筛选。** LncDrug 内部确认后选择零步回退，宏 AP 没有提升；MiDrug 宏 AP 从共同 TabM 的 0.717571 降至 0.716855。两个任务均未显示去噪优于无去噪集合模型。已有 56 个精排作业和 24 个初始模型，本次重新运行 12 项单元检查，并重算特征、重放全部检查点，均通过。详见 [正式报告](results/set_denoising_20260911/REPORT.md) 与 [本次复核及结论边界](results/set_denoising_20260911/recheck_20260911/RECHECK.md)。当前证据支持暂缓扩大该原型预算。

## 模型与四组对照

原型在一个固定的 TabM 初始模型上学习有界的 logit 修正。每种药物一次输入全部 1,322 个 lncRNA 或 605 个 miRNA；没有 top-K 预筛选、固定实体输出词表或训练好的节点 ID。每个候选独立输出关联分数，允许多个正例。

输入为当前支持图产生的 36 维配对特征、折外 TabM 分数、既有 PCA RNA 属性、药物属性、已知正关联标记及遮蔽时间。RNA/药物属性按行归一化。所有对照使用同样输入，新增属性与训练目标的收益不能单独归给去噪。

共享网络宽度 64、两层、dropout 0.1。候选交互通过 8 个槽聚合与回写，复杂度为候选数乘槽数；逐候选对照使用相同形状的投影，在每个 token 内计算门控，不能读取其他候选的新表示。

| 组名 | 候选交互 | 正例集合去噪 |
|---|---|---|
| `pointwise` | 无 | 无，固定终端遮蔽 |
| `set_plain` | 有 | 无，固定终端遮蔽 |
| `point_denoise` | 无 | 有 |
| `set_denoise` | 有 | 有，主候选 |

四组参数张量布局相同。无去噪组的时间输入固定，因此不能将相同参数数量解释成有效容量的严格等价。主候选的去噪贡献由它相对 `set_plain` 的增量判断；候选交互贡献由它相对 `point_denoise` 的增量判断。

修正为 `score = TabM_logit + 2*tanh(head(h))`，最后一层零初始化，所以第 0 步精确返回初始模型。训练期间第 0 步参与内部选模；选中回退必须如实报告为没有获得有效修正。

## 正例集合遮蔽与损失

先将拟合行分为五折。每次从一个查询折选择 16 种有查询行的药物，在完整候选集合上训练。整个查询折的标签都不参与初始模型拟合或结构特征构建。

给每个药物采样遮蔽概率 `t ∈ {0.25, 0.5, 0.75, 1}`，概率分别为 `1/6、1/6、1/6、1/2`。去噪组以 `1−t` 的概率显露该查询折中的正关联，作为其他候选可见的上下文；被显露的正例没有预测损失。未显露正例的损失乘 `1/t`，避免仅因遮蔽就改变预期正负权重。无去噪组始终使用 `t=1`，但保持相同药物抽样序列。

采样零标签始终作为未知状态，不转为“已确认负例”token。损失仍使用现有基准的零标签：按药物平均的 BCE，加 `0.0025 * logit修正²` 正则项。这是基准标签上的经验目标，不是经过识别假设验证的 PU 风险估计，也没有解决真实阴性缺失。

已知正例和临时显露正例的配对特征/初始分数在模型输入中统一置零，由正例标记和端点属性表示，避免两类正例上下文具有不同的占位规则。结构特征仍只来自基础拟合集，未因为额外显露标签而重算；它可以使用已知证据的子集，不能使用尚未显露的查询标签。

推理固定 `t=1`，仅给定训练正关联，一次前向得到全部候选的分数。本实现是正例集合遮蔽去噪的轻量原型，不是完整离散生成采样器，也不是 RADD/KREPE 的官方复现。

## 折外初始模型与数据边界

- 每个训练查询折单独拟合一个 TabM，排除该折全部正、零标签。该初始模型的训练结构特征再做五折生成，避免自己的正边进入自己的输入。
- 完整拟合集再拟合一个 TabM，用于内部留出或固定步数的外层评价。LncDrug 使用此前冻结的学习率 0.003、141 轮；MiDrug 使用 0.001、441 轮。初始模型结构与权重衰减沿用已有 TabM。
- 全部精排组和精排初始化共享同一组初始模型。因此三次精排初始化不代表三次独立的完整流水线重训。
- 每个场景都重新计算目标度数、路径、SVD 和属性支持统计。已知支持正例的结构特征留为占位零，不能作为该场景的未知查询评价。
- 其他 RNA 任务与 circRNA 信息沿用当前单任务协议，不能将本轮结果解释成严格冷药物实验。

## 冻结的实验设计

从原外层训练行中，用预先固定的种子 `2026091101` 划出 20% 新内部留出。新分组只用于本轮开发，不宣称是全新外部验证。原外层验证的标签在内部设置固定前不用于选模，测试集不载入。

每组分别比较两个学习率 `3e-4、1e-3`，权重衰减 `1e-4`；LncDrug 最多 400 个优化步骤，MiDrug 最多 600 个。每 20 步评价一次，用最近三次内部指标均值选一个实际检查点，指标为 `0.5*宏 AP + 0.25*(全局 AP + AUC)`，并与第 0 步比较。

先用种子 666 选择各组学习率，再用 0、1 确认，取三次选中步数的中位数，在原外层训练数据上固定步数重训三个初始化。正式计划包括 56 个精排作业及 24 个初始模型拟合；若中位步数为零，该外层作业是原样回退，没有执行优化。

预先记录的性能筛选：LncDrug 主候选相对共同 TabM 的宏 AP 平均提升至少 0.005；MiDrug 宏 AP 平均退化不超过 0.005；两任务全局 AUC/AP 平均退化分别不超过 0.001/0.002。这些容差用于原型筛选，不是统计非劣效证明。去噪和交互两个机制对照还各要求宏 AP 平均为正，且至少两个初始化为正。

同时报告原 GNN 在完全相同外层评价样本上的既有冻结结果，以判断是否补回原来的单药物排序。该 GNN 不参与本轮精排器选参。

除了按当前评测样本计算的 AUC/AP、药物宏 AP 和 Top-K，还报告在所有未观测 RNA 候选中的已知留出正例 Recall@20。后者只衡量已知留出正例的恢复，未知候选并非都是真阴性，不能据此计算实验阳性率。

## 使用与核验

在仓库根目录、`ncRNAdrug` 环境运行，设置 `OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4`。入口：

```bash
python -m unittest improve.test_set_denoising -v
python -m improve.set_denoising prepare --out-dir improve/results/set_denoising_20260911
python -m improve.set_denoising features --out-dir improve/results/set_denoising_20260911 --stage inner --task LncDrug --device cuda:0
python -m improve.set_denoising features --out-dir improve/results/set_denoising_20260911 --stage inner --task MiDrug --device cuda:1
python -m improve.set_denoising run --out-dir improve/results/set_denoising_20260911 --stage screen --task LncDrug --device cuda:0
```

两个任务可同时使用不同 GPU；同一任务有文件锁。其余阶段按 `--help` 中的顺序运行：完成两任务 `screen` 后 `select screen`，再 `run confirm`、`select confirm`、`features outer`、`run outer`、`report`、`validate`。最后重跑 `report` 汇总两个任务的核验结果。已完成作业只校验后跳过，不覆盖结果；若修改冻结源文件，应建立新实验目录。

12 项单元检查覆盖候选排列等变、真实候选交互、逐候选隔离、终端查询标签隔离、显露正例的损失排除、遮蔽权重、分折排除、全候选覆盖、梯度、有界修正和检查点回退。短流程还需验证两个任务的完整阶段转换。

正式核验会重算每个初始模型全部训练行的嵌套折外特征、抽样重算未知查询特征、重放所有初始模型和精排器检查点、复算指标及检查选模规则。`no_support`/`shuffle_support` 仅干预正例状态 token，固定结构特征与 TabM 分数，不代表删除全部图证据。

参考：[RADD](https://arxiv.org/abs/2604.25693)、[KREPE](https://arxiv.org/abs/2605.24064)、[本项目已有 TabM](GRAPH_TABM.md)。
